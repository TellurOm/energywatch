2. PROBLEM STATEMENT & SOLUTION
--------------------------------------------------------------------------------
Core Problem:
Traditional utility bills arrive 3 to 4 weeks after electricity has been consumed.
Consumers have zero real-time visibility into:
  1. Instantaneous power draw across household appliances.
  2. Disaggregation — which specific appliance (AC, Geyser, Refrigerator) drives peak costs.
  3. Realistic end-of-month bill forecasts before it is too late to make adjustments.
  4. Specific, measurable habits to lower both expenses and carbon emissions.

EnergyWatch Solution:
  1. Live Active Demand Monitoring: Visualizing real-time active load in kW.
  2. Consumption History & Peak Hour Highlighting: 24-Hour load profile showing residential
     evening peak hours (6:00 PM – 10:00 PM) in amber warnings.
  3. Appliance-Level Tracking: 10 appliances tracked with power ratings, daily runtimes,
     monthly kWh, efficiency ratings, and an interactive runtime adjustment simulator.
  4. Dual Tariff Bill Estimator: Supports both Flat Single Rate and Progressive Tiered Slab
     Billing with line-by-line itemized computation.
  5. Actionable Savings Engine: 6 prioritized habits with step-by-step guidance and dynamic
     cost/CO2 reduction tracking.


3. HARDWARE-READY DECOUPLED ARCHITECTURE
--------------------------------------------------------------------------------
Architecture Pipeline:
[ Physical IoT Sensors ]  -->  [ Microcontroller ]  -->  [ Network Transport ]  -->  [ EnergyDataSource ]  -->  [ EnergyRepository ]  -->  [ UI Layer ]
(SCT-013 CT Clamp /           (ESP32 / ESP8266)         (MQTT Broker / REST)        (Abstract Contract)        (Single Source of Truth)   (Flutter / Web)
 PZEM-004T AC Module)

Decoupling Principle:
The software architecture implements the Repository Pattern with an abstract EnergyDataSource.
Because physical sensors were simulated for this presentation prototype, future hardware
integration requires only writing a single ApiEnergyDataSource class. The UI, state management,
charts, and calculations require ZERO code modifications.

7. MATHEMATICAL FORMULAS
--------------------------------------------------------------------------------
1. Appliance Daily Energy:
   Energy (kWh) = Power (kW) × Runtime (hours)

2. Appliance Percentage Share:
   Share (%) = (Appliance Monthly kWh / Total Household Monthly kWh) × 100

3. Flat Rate Electricity Bill:
   Energy Charge = Consumption (kWh) × Rate (₹/kWh)
   Tax Charge = Energy Charge × (Tax % / 100)
   Total Bill = Energy Charge + Fixed Meter Charge + Tax Charge

4. Progressive Tiered Slab Bill (Utility Standard):
   For each Tier_i with bounds [Min_i, Max_i] and Rate_i:
     Units_in_Tier = min(Remaining_Units, Max_i - Min_i)
     Tier_Cost = Units_in_Tier × Rate_i
     Total_Energy_Charge = sum(Tier_Cost)
   Total Bill = Total_Energy_Charge + Fixed Charge + Tax Charge

5. Potential Monthly Cost Savings:
   Energy_Saved (kWh) = Monthly_Consumption × (Reduction_% / 100)
   Cost_Savings (₹) = Energy_Saved × Rate_per_kWh

6. Carbon Dioxide Emission Offset:
   CO2_Offset (kg) = Conserved_kWh × 0.82 kg CO2/kWh (Grid average factor)

9. TOP VIVA QUESTIONS & ANSWERS
--------------------------------------------------------------------------------
Q: Is this connected to real physical IoT hardware?
A: No, this is running on realistic simulated energy telemetry because physical CT clamp
   sensors and ESP32 microcontrollers were not connected to this device. However, the software
   is architected with an abstract EnergyDataSource contract, so connecting physical hardware
   via REST or MQTT requires zero changes to the UI or business logic.

Q: How does the progressive slab tariff work?
A: Instead of multiplying all units by a single rate, consumption is split into tiers:
   first 100 units at ₹4.50, next 100 units at ₹6.00, next 100 units at ₹8.00, and above 300
   at ₹10.00. This models actual utility billing accurately.

Q: Why build both Flutter and Plain HTML/CSS/JS?
A: Flutter provides a robust cross-platform mobile codebase for Android and iOS. The plain
   HTML5/CSS3/Vanilla JS version provides a lightweight (<80KB), instant-loading web app that
   has zero WebAssembly overhead and can be imported directly into Figma via html.to.design.
